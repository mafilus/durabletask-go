# v1.1.0: idempotent external event delivery

## New capability

`RaiseEvent` now accepts a durable external delivery identity:

```go
client.RaiseEvent(ctx, instanceID, "order.created",
    api.WithEventPayload(payload),
    api.WithExternalDeliveryID(messageID),
)
```

For a non-empty delivery ID, SQLite and PostgreSQL atomically persist a receipt
keyed by `(instanceID, eventName, deliveryID)` together with the new event. A
retry with the same key succeeds without appending a second `EventRaised` to
the workflow history. This supports an outbox publisher that can crash after
`RaiseEvent` succeeds and before it marks its own message as published.

The engine deliberately does not provide outbox leases, retries, poison
handling, topic routing, or projections. Those remain the publisher's
responsibility.

## PostgreSQL upgrade

Before deploying a process that sends or accepts external delivery IDs, apply
the migration to every task-hub database:

```sh
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 \
  -f docs/migrations/postgresql/v1.1.0_external_event_deliveries.sql
```

The migration is idempotent. It is required for already provisioned hubs
because `OpenTaskHub` intentionally does not apply schema DDL. Newly created
hubs receive the table from the bundled schema.

For SQLite, `CreateTaskHub` applies the bundled idempotent schema on startup;
no separate SQL command is required.

## Safe rollout order

1. Apply the PostgreSQL migration to every relevant database.
2. Deploy v1.1.0 servers everywhere a `RaiseEvent` request can be handled.
3. Only then enable publishers to send `externalDeliveryId`.

Older gRPC servers do not understand this optional field and can treat such a
request as an ordinary event. Sending delivery IDs before step 2 would lose the
at-least-once deduplication guarantee.

## Compatibility

The new protobuf field is optional and normal `RaiseEvent` calls are unchanged.
An explicitly supplied empty delivery ID is rejected. Custom backends must
implement `backend.ExternalEventDeliveryBackend` before callers enable this
option; otherwise the request fails closed with
`backend.ErrExternalDeliveryUnsupported`.
