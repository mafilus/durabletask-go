# v1.2.2: retry replay, worker recovery and security fixes

- Fix retries after successful-result decoding errors and repeated `Await` calls;
  preserve deterministic execution identities during replay.
- Accept gRPC work items up to 16 MiB by default, with a configurable budget.
  Retry temporary resource errors twice, then report terminal exhaustion through
  an optional listener error handler.
- Reject duplicate completion registrations before dispatch and preserve the
  original waiter.
- Record early-resolved schedules with their historical identity, without
  redispatching completed work.
- Require Go 1.26.10 and update `golang.org/x/net` to v0.60.0 for security fixes.
  Builders using Go 1.27 must use 1.27.3 or newer.

## Upgrade notes

No schema migration is required. Unmarked retry histories retain legacy behavior;
keep marked histories on upgraded workers. Custom hosts must persist workflow
patch metadata and adopt the matching record-without-dispatch applier behavior.
Configure server message limits and monitor listener termination as needed; the
resource-error retry budget is finite. See the
[maintenance guide](https://github.com/mafilus/durabletask-go/blob/v1.2.2/docs/october-maintenance.md)
for the API and integration details.
