# v1.0.0 migration: removal of workflow rerun

## Breaking change

`RerunWorkflowFromEvent` has been removed from this fork's public Go API,
gRPC service, protobuf definitions, backend interfaces, and generated client
stubs.

The operation was exposed by historical upstream protobuf definitions but was
never implemented by the bundled SQLite or PostgreSQL backends. Its known
runtime implementation belongs to Dapr's workflow Actors backend and relies on
Actors-specific state forking. That behavior is outside this fork's generic
storage and execution contract.

## Migration

If an application needs a new business execution, schedule a new workflow
instance with a new instance ID and let the application record any lineage,
reason, and idempotency policy. Do not treat transport retries as a new
execution: retry the original request according to the application's
idempotency contract.

Applications that require Dapr Actors rerun must remain on the Dapr module and
protobuf contract that provides it. This fork makes no compatibility promise
for Dapr's workflow Actors protocol or its persisted histories.

No SQLite or PostgreSQL data migration is required. The bundled backends never
persisted rerun state. Removed protobuf field numbers and names are reserved in
the fork's schema and will not be reused.

## Upgrade impact

- Go callers must replace `RerunWorkflowFromEvent` and `WithRerun*` calls with
  an application-defined new workflow execution.
- gRPC callers must stop invoking `TaskHubSidecarService.RerunWorkflowFromEvent`.
- Custom backends no longer implement a rerun method as part of `backend.Backend`.
- Generated clients and servers must be regenerated from this fork's pinned
  protobuf definitions.
